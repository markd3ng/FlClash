# Windows 本地配置恢复

当配置密钥缺失、存储访问失败或配置无法解密时，恢复页展示对应原因，并允许重试

## 恢复与重置

- Windows 密钥文件沿用 `flutter_secure_storage.dat` 的 DPAPI 加密 JSON 格式
- 所有键共享串行队列和文件锁，写入使用临时文件、刷新及原子替换
- 读取顺序为当前文件、`.old`、`.tmp`，有效候选可以恢复当前文件
- 读取失败不会清除密钥文件；恢复时留存的损坏文件副本也会再次加密
- 无法恢复时，Windows 恢复页提供“备份并重置”，确认后创建加密备份，成功后退出并重新打开应用
- 重置会清除当前设置、订阅、规则和账号状态，需要重新登录并恢复或导入设置、订阅
- 备份不能重新生成已丢失的旧配置密钥

## 备份保护

备份位于应用数据目录的同级 `clash.recovery-*` 目录，其中只有编号 `.enc` 文件及 `manifest.enc`

文件内容、原始文件名、路径、符号链接目标和完整性信息均加密，包含 oixCloud DNS、节点和账号数据的文件不会以明文副本或明文临时文件落盘

生产加密使用 Windows 当前用户的 DPAPI，不在备份目录写出解密密钥，不使用明文降级策略。备份受当前 Windows 用户保护，属于本机恢复资料，不是跨设备明文订阅导出

大文件按 64 KiB 分块加密，每帧以大端 32 位长度开头。加密清单版本为 1，包含文件长度和 SHA256；验证会拒绝截断、损坏及内容不匹配的备份

加密备份完成且能成功解密校验后，才写入加密重置日志 `.config-recovery.dat` 并移除原始数据。删除前检查原数据与备份一致，发现变化时停止

中断后的启动顺序是：取得单实例锁、继续已确认的重置、旧目录迁移、旧备份事务恢复、加载配置。完成的重置不会再次清除新配置，应用锁始终保留

恢复页只显示备份位置。`ConfigBackup.verify` 和 `readFile` 可供受控恢复代码验证、读取加密归档，不提供明文 DNS 或节点导出入口
