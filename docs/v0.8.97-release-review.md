# v0.8.97 发布审查

范围：复核上游 v0.8.97 的核心、界面、数据库与平台迁移，并处理 Android 9/13 弱网延迟测试及 Windows 开机静默启动反馈

## 修复与整理

- 手动测速共享并发上限从 50 降至 8，Android 批量首轮使用 4 路；出现连续失败或慢响应后降至 2 路，减少探测本身对弱链路的争抢
- 首轮保持 5 秒网络预算，只对失败节点复测一次，复测预算 15 秒、并发 2 路；单节点测试使用同样的失败复测预算，成功结果立即显示
- RPC 预算随网络预算增加 2 秒余量，换配置或新一轮测速后继续丢弃过期结果和排队工作；真正不可达的节点仍显示失败
- SSID 暂停／恢复任一步骤失败时，将已应用状态置为未知，下次同时协调 Core 和 VPN；清空排除列表后保留轮询，直到恢复成功
- setup.dart 删除已失效的工具函数及重复字段，命令参数改为结构化列表，支持带空格路径，任何子命令非零退出都会终止构建并保留脱敏错误
- 修复发布 CI 对 Dart CLI 使用不支持的 `--no-fatal-infos` 参数；`dart analyze` 默认不将 info 视为失败，仍检查 warning 和 error
- 修复 Linux NDK 不附带 libclang 时过早拒绝 Android Rust 构建的问题：优先显式主机库路径，再查 NDK，最后允许 clang-sys 发现已安装的系统库；补充 5 项回归
- Windows 配置重置回归使用原生目录分隔符构造嵌套文件名，并通过持锁句柄检查锁文件内容，兼容 Windows 强制字节锁；未改动备份格式或重置行为
- Windows 对已经隐藏的窗口不再调用 `ShowWindow(SW_HIDE)`，避免首次调用被启动器的 `STARTUPINFO` 显示指令覆盖；自动更新仅在应用内提示，用户手动检查更新时才显示窗口；清理原生启动中无作用的首帧回调和过期说明
- 构建号下限设为 `2026092917`，高于用户反馈中的 `2026092916`；CI 使用时钟编号与 pubspec 下限的较大值，避免 Android 覆盖安装被误判为降级

旧 `plugins/tray_manager`、`third_party/quickjs-c-bridge` 及其 Linux/Windows 构建胶水仍保留在仓库中，当前依赖和平台构建使用 `plugins/tray` 与 `rust_api`，没有引用旧实现；删除操作尚待具体路径授权，不影响当前构建
